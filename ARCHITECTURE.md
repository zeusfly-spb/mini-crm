# Сопроводительный файл по проекту Mini CRM

## Цель проекта

`Mini CRM` — компактная система приёма и обработки заявок:
- клиент отправляет заявку через виджет;
- заявка сохраняется и попадает в административный интерфейс;
- менеджер просматривает и меняет статус заявки.

## Почему выбран Laravel 11

- Быстрый старт и понятная структура проекта (роуты, контроллеры, модели, миграции, тесты).
- Eloquent упрощает работу со связями (`Customer` ↔ `Ticket`).
- Удобная встроенная валидация входных данных.
- Простая интеграция с тестами (`Feature`/`Unit`) и инструментами разработки.

## Основные архитектурные решения

### 1) Разделение по зонам ответственности

- `WidgetTicketController` отвечает за публичный ввод заявок.
- `TicketController` отвечает за административную часть (просмотр и обновление статусов).
- Модели:
  - `Customer` — клиент;
  - `Ticket` — заявка.

Такое разделение упрощает поддержку: публичная и админская логика не смешиваются.

### 2) Связи данных

- У одного клиента может быть много заявок (`Customer hasMany Ticket`).
- Заявка принадлежит клиенту (`Ticket belongsTo Customer`).

Это позволяет:
- переиспользовать клиента по `email`;
- фильтровать заявки через данные клиента (email/phone).

### 3) Ограничение на отправку заявок

Реализовано правило: не более одной заявки в сутки с одного `email` или `phone`.

Почему это сделано:
- защита от дублирующих обращений и спама;
- снижение нагрузки на менеджеров;
- более чистая очередь заявок.

Технически ограничение проверяется в `WidgetTicketController@storeApi` до создания записи.

### 4) Статусы заявки как константа модели

Статусы (`new`, `pending`, `resolved`) вынесены в `Ticket::STATUSES`.

Почему:
- единый источник правды для интерфейса и валидации;
- меньше риска рассинхронизации между контроллером и представлениями.

## Почему выбраны библиотеки

- `darkaonline/l5-swagger` + `zircote/swagger-php`  
  Для автоматической документации API и прозрачной интеграции с Laravel.

- `spatie/laravel-medialibrary`  
  Для хранения и выдачи файлов-вложений к заявкам без ручной реализации файлового слоя.

- `spatie/laravel-permission`  
  Для потенциального расширения авторизации/ролей в админке.

- `laravel/sanctum`  
  Базовый современный механизм API-аутентификации Laravel (готов к расширению проекта).
